# make-video

규칙의 전체 그림은 `CLAUDE.md`에 있다. 이 스킬은 순서만 정한다. 값은 docs에서 찾고, 여기에 베껴 적지 않는다.

## 0. 영상 이름
- 사용자와 짧은 영어 이름을 정한다(예: `mission-approved`). 모든 결과는 `out/<영상이름>/`에 둔다.

## 1. BRIEF (메인이 직접)
사용자에게 세 가지만 묻는다. 질문마다 기본값을 같이 준다.
1. **무엇을** 보여 줄까? 기본값: 화면 하나와 그 화면의 부품 하나 (목록은 `docs/design.md` 6장)
2. **몇 초**? 기본값: 15초
3. **레퍼런스**는? (링크 · 파일, 여러 개면 뼈대 하나 + 역할) 기본값: `references/`에 이미 있는 영상 (`references/sources.md`)

답을 `out/<영상이름>/BRIEF.md`에 적는다. 사용자가 "기본값"이라고 하면 기본값 그대로 적는다.

## 2. 레퍼런스 정리
- `art-director` 에이전트를 부른다 → `reference.md`

## 3. 장면표 — 승인 1
1. `director`를 부른다 → `scenes.md`에 3안 요약
2. `critic`으로 3안 요약을 판정한다(숫자 · UI만, 반영률은 안마다 적힌 번호로).
3. 3안 요약을 보여 주고 판정 한 줄을 붙여 사용자에게 **하나를 고르게** 한다.
4. 고른 안으로 `director`를 다시 불러 장면표를 쓴다 → `critic` 판정
5. 새 후보가 있으면 이때 한꺼번에 묻는다.

## 4. 스냅보드 — 승인 2
1. `builder`를 부른다 → `snapboard.png` · `index.html`
2. `critic`으로 판정한다.
3. 스냅보드를 **먼저 보여 주고** 판정 한 줄을 붙인다. 사용자가 승인해야 다음으로 간다.

## 5. 영상
1. `builder`로 렌더한다 → `<영상이름>.mp4`
2. `critic`으로 판정하고, 영상을 먼저 보여 준 뒤 판정 한 줄을 붙인다.

## 불합격일 때
- critic 판정에 적힌 곳만 담당 에이전트에게 돌려보내 고친다(장면표는 `director`, 스냅보드 · 영상은 `builder`).
- **같은 곳**(같은 비트의 같은 항목)에서 두 번 떨어지면 더 고치지 말고 멈춘다. 두 번의 판정을 보여 주고 사용자에게 어떻게 할지 묻는다.

## 하지 않는 것
- 승인 1 · 승인 2를 건너뛰기
- `docs/` · `src/` 고치기 (필요하면 사용자에게 먼저 묻기)
- 레퍼런스에서 색 · 글자 · 로고 · 숫자 가져오기
